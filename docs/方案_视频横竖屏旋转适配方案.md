# 视频横竖屏适配方案 — Rotation 感知

> 基于代码审查和链路追踪的完整执行方案
> 覆盖：元数据扫描 → AI 管线缩略图 → 下游服务帧分析 → 前端展示

---

## 一、问题分析

### 1.1 问题来源

手机等设备拍摄的视频在编码时，通常存储为“原始传感器方向”（横），但在容器中写入 `rotation` 元数据标记（如 `rotate=90`）来指示实际显示方向。当前代码在所有环节都忽略了该标记。

### 1.2 受影响的完整链路

| 阶段 | 文件 | 函数 | 问题 |
|------|------|------|------|
| 元数据提取 | `server/app/core/indexer.py` | `_raw_extract_metadata()` | 未读 `tags.rotate`，DB 存储未校正的 raw wh |
| AI 管线初始化 | `server/ai_service/pipeline.py` | `AIPipeline.run()` Step 0 | 用 `cv2.VideoCapture` 取 raw wh，未检测 rotation |
| 缩略图生成 | `server/ai_service/services/scene_service.py` | `extract_thumbnail()` | `cv2.imencode` 存的是侧躺帧 |
| YOLO 检测 | `server/ai_service/services/yolo_service.py` | `detect_scene_objects()` | 帧分析前未旋转校正 |
| OCR 识别 | `server/ai_service/services/ocr_service.py` | `ocr_scene_middle()` | 帧分析前未旋转校正 |
| CLIP 编码 | `server/ai_service/services/clip_service.py` | `encode_frames()` | 帧编码前未旋转校正 |
| 前端显示 | `web/src/pages/AssetDetailV2.tsx` | `getResolutionLabel()` | wh 来自 DB，错标横竖屏 |

### 1.3 架构关键约束

**AI Pipeline 与元数据扫描是两条独立路径：**

- 扫描器（indexer.py）用 ffprobe 提取 wh 写入 PG `assets` 表
- AI Pipeline（pipeline.py）用 `cv2.VideoCapture` 重新获取 wh 写入 SQLite `videos` 表
- 两者互相不通信

因此 **不能** 只在 indexer 修了就算完 — AI 管线侧必须独立处理。

## 二、方案架构

### 2.1 分层策略

```
Layer 1: 元数据层 (indexer.py)
  - 读取 ffprobe tags.rotate / display_matrix
  - 校正 width/height → 存入 DB
  - rotation 值仅用于 AI 管线层，不写入 PG（Asset 模型无 rotation 列）

Layer 2: AI 管线层 (新增 utils/rotation.py + 修改 service*.py)
  - 全局 utility: get_video_rotation(path) → int
  - 每个取帧的服务在 cap.read() 后做 cv2.rotate()
  - 缩略图场景: 取帧→旋转→保存

Layer 3: 前端层 (AssetDetailV2.tsx)
  - DB wh 已校正 → getResolutionLabel 自动正确
```

### 2.2 不受影响的部分

| 模块 | 原因 |
|------|------|
| TransNetV2 场景检测 | 场景边界依赖于帧间视觉差异，旋转不影响边界位置 |
| Whisper / 音频管线 | 音频与视频方向无关 |
| 前端 CSS 渲染 | 缩略图方向已校正，object-fit: cover 正常 |
| 数据库 Schema | 无需加列（已有 width/height） |

## 三、详细修改

### 3.1 新增文件：`server/ai_service/utils/rotation.py`

"""Video rotation detection utility.

Detects display rotation from ffprobe tags and side data.
Used by all services that read video frames.
"""

import json
import subprocess
from pathlib import Path
from typing import Optional


def get_video_rotation(video_path: str | Path) -> int:
    """Detect the intended display rotation of a video file.

    Checks (in order):
      1. Stream tags.rotate (most common, used by phones/tablets)
      2. Side data display_matrix (rare, alternative encoding)

    Returns:
        0, 90, 180, or 270 degrees
    """
    cmd = [
        "ffprobe", "-v", "quiet",
        "-print_format", "json",
        "-show_streams",
        str(video_path),
    ]
    try:
        result = subprocess.run(cmd, capture_output=True, text=True, timeout=15)
        data = json.loads(result.stdout)
        for stream in data.get("streams", []):
            if stream.get("codec_type") != "video":
                continue
            tags = stream.get("tags", {})
            rotate_tag = tags.get("rotate")
            if rotate_tag is not None:
                return int(rotate_tag) % 360
            side_data_list = stream.get("side_data_list", [])
            for sd in side_data_list:
                if sd.get("side_data_type") == "Display Matrix":
                    r = sd.get("rotation")
                    if r is not None:
                        return int(r) % 360
        return 0
    except Exception:
        return 0


def apply_rotation(frame, rotation: int):
    """Rotate an OpenCV frame according to display rotation."""
    import cv2

    if rotation == 90:
        return cv2.rotate(frame, cv2.ROTATE_90_CLOCKWISE)
    elif rotation == 180:
        return cv2.rotate(frame, cv2.ROTATE_180)
    elif rotation == 270:
        return cv2.rotate(frame, cv2.ROTATE_90_COUNTERCLOCKWISE)
    return frame
