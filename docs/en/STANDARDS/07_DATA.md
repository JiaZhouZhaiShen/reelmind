# 07 Data Standard

> Rules: R6.1-R6.3 (EN mirror of `docs/规范/07_数据规范.md`; the Chinese file is authoritative)
> Purpose: boundaries for database changes, backups, and deletion. Data is the project's least renewable asset (video metadata + AI inference results) and outranks all code.

---

## R6.1 Model Changes Go Through Migrations

Boundary: changing SQLAlchemy models (`server/app/models/`) or needing table structure changes requires an alembic migration; manual `ALTER TABLE` / `CREATE TABLE` is forbidden.

```bash
# OK standard flow
# 1. Edit the ORM files under models/
# 2. Generate the migration
docker compose exec reelmind-server alembic revision --autogenerate -m "description"
# 3. Review the generated migration (autogenerate can misjudge; review the diff manually)
# 4. Apply it
docker compose exec reelmind-server alembic upgrade head
# 5. Verify the schema
docker compose exec postgres psql -U reelmind -c "\d table_name"
```

Forbidden:
- Running `psql -c "ALTER TABLE ..."` directly on production tables (except emergencies with a backup taken first)
- Changing models without generating a migration (model/schema drift -> runtime crashes)
- Applying autogenerated migrations without review

Check:
```bash
# DDL outside migration directories is a violation
grep -rn "ALTER TABLE\|CREATE TABLE\|DROP TABLE" server/app/ server/ai_service/ --include="*.py" | grep -v alembic
```

## R6.2 Back Up Data Before Touching It

Boundary: any database write (migration / cleanup / import / large UPDATE) requires backing up the database first. Same level as R0.3 (code backups); it cannot be skipped.

```bash
# PG backup
docker compose exec postgres pg_dump -U reelmind -F c -f /tmp/reelmind_$(date +%Y%m%d).dump reelmind

# SQLite backup (copy the .db file)
cp data/reelmind.db backups/20260902_data_change/reelmind.db
```

Forbidden:
- Running migrations/cleanups/imports without a backup
- Using "it is only a test environment" as an excuse to skip backups

Check: manual process; `scripts/backup.sh` supports database backup (see its docs).

## R6.3 Deletion Closes the Loop

Boundary: deleting an asset requires cleaning up all related data at the same time; orphaned data is forbidden.

| Deleted object | Must also clean |
|----------------|-----------------|
| Asset | scenes, subtitles, tags, OCR, CLIP vectors, ai_engine_jobs records, preview files |
| Library | all assets in the library + their related data |
| Tag | all asset_tags associations |

Forbidden: deleting only the primary record and leaving orphaned scenes/subtitles/vectors (causes frontend display bugs, dirty search data, storage leaks).

Check: deletion-interface code review must verify the related cleanup logic.
