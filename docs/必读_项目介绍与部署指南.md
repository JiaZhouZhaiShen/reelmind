# ReelMind 项目介绍与部署指南

> 版本：2026-09-02
> 定位：自托管 AI 视频库管理系统，为剪辑团队 / 创作者 / AI Agent 设计，专注视频（对标 IMMICH 的图片方向）。
> 本文档基于仓库实际配置编写，命令均已按 `docker-compose.yml` / `.env.example` / `CLAUDE.md` 验证。

## 一、项目基本介绍

**ReelMind** 是一个自托管（self-hosted）的视频资产库管理系统，可管理数千条视频资产，并自动提取场景、字幕、物体标签、OCR 文字、CLIP 语义向量，提供全文搜索 + 语义搜索的混合检索能力。

核心特性：**AI 推理管线与 Web API 完全解耦**——Web 服务不加载任何 AI 模型，AI 计算跑在独立 GPU 容器中，通过 HTTP 代理转发，保证 AI 满载时 Web API 不卡顿。

### 系统架构（6 个容器 + 1 网络）

| 容器 | 端口 | GPU | 镜像 | 职责 |
|------|------|-----|------|------|
| `reelmind-server` | 内部（经 nginx） | ❌ | `server/Dockerfile.slim` | FastAPI 网关、AI 代理、文件扫描、Web 后端、静态文件 |
| `reelmind-ai` | 2589 | ✅ | `server/ai_service/Dockerfile` | AI 管线编排（5 个模型），独立镜像与显存 |
| `reelmind-orchestrator` | — | ❌ | `server/orchestrator/Dockerfile` | 轻量作业调度器（替代 Celery Beat） |
| `reelmind-postgres` | — | — | `pgvector/pgvector:pg16` | 资产元数据 + pgvector 向量索引 |
| `reelmind-redis` | — | — | `redis:7-alpine` | 缓存、队列、进度 pub-sub |
| `reelmind-nginx` | **2588**（对外） | ❌ | `nginx/Dockerfile` | 反向代理、视频零拷贝分发、静态资源 |

**数据流**：

```
客户端 → nginx(2588) → reelmind-server
  ├── 非 AI 请求 → PostgreSQL / SQLite / 文件系统
  └── /api/ai/* → HTTP 代理 → reelmind-ai(2589) → 结果写共享 SQLite
Orchestrator: 轮询 PG → 调度 AI 作业 → 更新 ai_engine_jobs
```

**存储约定（双库分离）**：
- **PostgreSQL**：资产元数据、管道状态（`ai_engine_jobs`）、pgvector 向量
- **SQLite**（`data/reelmind/reelmind_ai.db` 等）：AI 推理结果（场景/字幕/标签/OCR）
- 状态驱动调度，结果驱动展示，二者不混写

## 二、主要功能

### 视频库管理
- 多库组织：创建多个视频库，分类管理数千条资产
- 外部库挂载：支持本地磁盘 / NAS / 网络共享直接引用文件（只读挂载，不拷贝）
- 批量导入与扫描：自动发现新文件、索引入库
- 元数据提取：ffprobe 提取编码 / 分辨率 / 帧率 / 时长 / 码率 / 音轨信息

### 检索能力
- 全文搜索：文件名、备注、字幕文本
- 智能搜索：元数据 + 标签 + 字幕内容的组合检索
- 标签系统：手动标签 + AI 自动标签，带分类管理
- **语义搜索**：CLIP 向量相似度（需启用 AI）

### 预览与播放
- 缩略图网格：自动为每个视频生成缩略图
- 代理视频：轻量 H.264 代理流，Web 播放流畅（可调码率/宽度）
- 场景浏览器：自动切分的场景段 + 逐场景缩略图
- 网页播放器：浏览器内播放，支持字幕时间轴叠加

### AI 管线（可选启用）
| 模型 | 用途 | 模型权重 |
|------|------|---------|
| TransNetV2 | 场景切割 | — |
| YOLOv8n | 物体检测 / 自动标签 | 8.3.0 |
| PaddleOCR | 画面文字识别 | 2.8.0 |
| OpenCLIP | 语义向量（相似搜索） | ViT-B-16 |
| faster-whisper | 语音转文字 | large-v3 / tiny 等 |

AI 管线按序执行：场景切割 → 物体检测 → OCR → CLIP 向量 → 语音转写（+ 可选说话人分离）。

### API 与集成
- REST API：完整 JSON 接口，供外部工具 / AI Agent 调用
- 异步作业：Orchestrator 调度管道
- 健康检查：`/api/ping`、`/health`、系统状态面板

## 三、能够实现的目标

1. **剪辑素材库的 AI 大脑**：给剪辑团队一个"可搜索的素材库"——不靠记忆找素材，靠内容找素材（字幕、物体、场景、语义相似）。
2. **AI 逐条资产自动标注**：扫描入库后自动产出场景切分、文字识别、语音转写、物体标签，无需人工逐条整理。
3. **混合检索落地**：同一视频既可按文件名搜，也可按"说了什么话 / 画面里有什么 / 语义相近"搜。
4. **Web 端协作浏览**：团队在浏览器即可浏览、检索、预览素材，视频通过 nginx 零拷贝分发，拖资源占用小。
5. **对 AI Agent 开放**：REST API 让 Agent 能接入检索与任务触发，未来演进为"AI 工作台"。

## 四、系统依赖清单

> 依赖分三层：**宿主机系统依赖**（容器外必装）、**镜像内置依赖**（Dockerfile 自动装，部署者了解即可）、**运行时模型**（首次运行自动下载）。

### 4.1 宿主机系统依赖（重新部署前必装）

| 依赖 | 版本要求 | 用途 | 必须 |
|------|---------|------|------|
| Docker Engine + Compose v2 | 20.10+ / compose v2 | 容器编排 | 🔴 |
| NVIDIA 驱动 + `nvidia-container-toolkit` | 支持 CUDA 12.4 | AI 容器 GPU 加速（`runtime: nvidia`） | 🔴 用 AI 时必须 |
| `openssl` | 任意 | 生成 `JWT_SECRET` | 建议 |
| 磁盘空间 | 数据目录 ≥ 50GB 起 | PG + SQLite + 媒体 + 模型缓存 | 🔴 |
| `ffmpeg` / `ffprobe` | 见 4.2 | **仅本地开发**需要（容器内已内置） | 非必须 |

### 4.2 容器镜像内置依赖（Dockerfile 声明，无需手动装）

**所有容器基础**：Linux + Python 3.12（ai/orchestrator）+ Python 3.x slim（server）

| 容器 | 系统包 (apt) | Python 依赖来源 |
|------|-------------|----------------|
| `reelmind-server` | `ffmpeg curl tini` | `server/requirements.txt` |
| `reelmind-ai` | `python3.12 ffmpeg curl tini`（deadsnakes PPA） | `server/ai_service/requirements.txt` |
| `reelmind-orchestrator` | 无额外系统包 | `server/orchestrator/requirements.txt` |
| `reelmind-postgres` | 镜像自带 | —（`pgvector/pgvector:pg16`） |
| `reelmind-redis` | 镜像自带 | —（`redis:7-alpine`） |

**关键 Python 依赖**（三份 requirements 实测）：

- **server**（Web 网关）：`fastapi / uvicorn / sqlalchemy / asyncpg / psycopg2-binary / alembic / pgvector / redis / pydantic / python-multipart / ffmpeg-python / opencv-python-headless / httpx / passlib+bcrypt / python-jose` 等
- **ai_service**（GPU 推理）：`torch 2.5.1 + torchvision + torchaudio`、`transnetv2-pytorch`、`ultralytics 8.3.0`、`paddleocr 2.8.0 + paddlepaddle 3.3.1`、`open-clip-torch 2.29.0`、`faster-whisper 1.1.1`、`pyannote.audio 3.1.1`、`scenedetect 0.6.2` 等
- **orchestrator**：轻量调度依赖（`server/orchestrator/requirements.txt`）

### 4.3 前端依赖（构建 web/dist 用）

`web/package.json` 实测核心：`react 18.3.x`、`react-dom`、`zustand 4.5.2`、`vite 5.3.x`、`i18next 26.x`、`typescript 5.4.x`。用 `npm install` 安装（Node.js 需满足 vite 要求，建议 Node 18+/20+）。

### 4.4 运行时模型（首次运行自动下载到数据卷）

AI 容器首次跑管线时自动下载模型到 `/data/reelmind/models`（挂载卷），下载需联网：

| 模型 | 体积参考 | 对应功能 |
|------|---------|---------|
| faster-whisper `large-v3` | ~3GB+ | 语音转写（`WHISPER_MODEL` 可改 `tiny` 省资源） |
| open-clip `ViT-B-16` | ~350MB | 语义向量 |
| PaddleOCR | ~几十 MB | 画面文字 |
| YOLOv8n | ~6MB | 物体标签 |
| pyannote diarization | ~数百 MB | 说话人分离（需 `HUGGINGFACE_TOKEN`） |

> 模型下载失败排查：检查 `data/reelmind/models` 卷可达性、磁盘空间、网络；HF 模型需能访问 huggingface.co。

## 五、重新部署步骤

> 前提：Docker + Docker Compose v2、NVIDIA GPU + nvidia-container-runtime（AI 容器需要，若不用 AI 可临时去掉 `runtime: nvidia`）。
> 时间基准：本地磁盘 / 群晖 NAS 均可；`./data` 数据目录需有足够空间（含模型缓存 + AI 结果库）。

### 第 1 步：准备项目目录与配置文件

```bash
# 进入项目根目录（含 docker-compose.yml 的目录）
cd reelmind    # 从 GitHub clone 的仓库目录；本机路径请用你自己的项目路径

# 生成 .env（若不存在）
cp .env.example .env
```

**从 GitHub clone 部署须知**（首次 git clone 场景）：

| 项 | 说明 |
|----|------|
| `.env.example` 已入库 | 模板含占位符（`change-me`），不含真实密钥，clone 后直接 `cp` 即可 |
| **镜像：GHCR 可选，默认本地构建** | 自建镜像已发布 `ghcr.io/jiazhouzhaishen/*`（Public）；不设 `REELMIND_*_IMAGE` 时仍本地 `docker compose build`，设置后 `docker compose pull` 拉取（见 README）；postgres / redis 用官方镜像 |
| **Node 版本** | 前端构建需 Node.js ≥18（Vite 5 要求），建议 20 LTS；无 `.nvmrc`，请自行满足 |
| **media/ 样例不入库** | clone 后 `media/` 需自建或挂载外部目录（见 `.env` 的 `EXTERNAL_MEDIA_DIR`） |
| **data/ 目录不入库** | 数据（PG/SQLite/模型缓存）均在运行时生成，clone 后为空属正常 |
| 模型权重不入库 | AI 模型首次运行自动下载到数据卷（见 4.4） |

### 第 2 步：编辑 `.env`（关键项）

| 项 | 必须改 | 说明 |
|----|--------|------|
| `DB_PASSWORD` | 🔴 是 | 生产环境替换为强密码 |
| `JWT_SECRET` | 🔴 是 | 生成随机密钥：`openssl rand -hex 32` |
| `EXTERNAL_MEDIA_DIR` | 按需 | 媒体库目录（NAS 示例 `/volume1/video/footage`） |
| `REELMIND_DATA_ROOT` | 按需 | 数据目录（默认 `./data/reelmind`） |
| `PGDATA_ROOT` | 按需 | PG 数据目录（默认 `./data/postgres`） |
| `PORT_MAP` | 按需 | 对外端口（默认 `0.0.0.0:2588`） |
| `ENABLE_WHISPER` / `WHISPER_MODEL` | 按需 | 是否启用语音转写；NAS 建议 `tiny`，有显存用 `large-v3` |
| `ENABLE_CLIP` | 按需 | 是否启用语义向量（约 +2GB 内存） |
| `HUGGINGFACE_TOKEN` | 启用 diarization 时 | 说话人分离需要 HF 令牌 |
| `AI_MEM_LIMIT` / 各 `MEM_LIMIT` | 按需 | 低内存设备调低（NAS 4GB 参考 `.env.example` 注释） |

### 第 3 步：构建前端（web/dist 以只读卷挂载进容器）

```bash
cd web
npm install        # 安装依赖（首次）
npm run build      # 构建产物到 web/dist/
cd ..
```

> 注意：`web/dist` 被容器以 `:ro` 挂载，**必须先构建**再起容器，否则页面 404。

### 第 4 步：构建镜像并启动

```bash
# 构建全部镜像（首次较慢，含模型下载环境）
docker compose build

# 启动
docker compose up -d
```

> 从 GHCR 部署时跳过本地构建：设置 4 个 `REELMIND_*_IMAGE` 环境变量（如 `REELMIND_SERVER_IMAGE=ghcr.io/jiazhouzhaishen/reelmind-server:v9.26.0901`）后执行 `docker compose pull && docker compose up -d`。前端 `web/dist` 仍需先本地构建一次（v1 边界，见 README）。

### 第 5 步：验证健康状态

```bash
# 1. 容器状态
docker compose ps          # 所有容器应为 Up（healthy）

# 2. Web / API
curl http://localhost:2588/api/ping

# 3. AI 服务
curl http://localhost:2589/health

# 4. 打开浏览器
# http://localhost:2588
```

### 第 6 步：首次使用流程

1. 浏览器打开 Web UI
2. **首次登录（重要）**：点注册，创建第一个账号——**第一个注册用户自动获得 admin 角色**（源码 `auth.py` 逻辑，无预设初始账号；`register` 需 `username` ≥2 字符、`password` ≥6 字符）
3. 用该 admin 账号登录 → 创建库
4. 在设置中指定媒体目录（即 `.env` 的 `EXTERNAL_MEDIA_DIR`）
5. 触发"扫描媒体库" → server 索引资产元数据
6. 可选：触发 AI 管线（单视频 / 批量）→ AI 容器开始跑 5 模型 → 结果写 SQLite
7. 在搜索页体验全文 / 语义搜索

### 第 7 步（可选）：数据库迁移

```bash
# 若升级版本后表结构变化，容器启动会自动跑 alembic upgrade head
# 手动执行：
docker compose exec reelmind-server alembic upgrade head
```

## 六、部署注意事项

### 1. 安全（必读）
- **默认密码不安全**：compose 中多处 `change-me` / `reelmind` 是开发默认值，生产必须改：`DB_PASSWORD`、`JWT_SECRET`、`HUGGINGFACE_TOKEN`。
- **.env 禁止入库**：仓库 `.gitignore` 已排除 `.env`；不要 `git add -f .env`。
- **无 docker.sock 挂载**：已移除，杜绝容器逃逸风险。
- 对外暴露请务必走 HTTPS（建议前置反向代理）。

### 2. 前端构建顺序（最容易踩的坑）
`web/dist` 是只读挂载进 nginx 与 server 的。**改前端代码后必须重新 `npm run build` 才能生效**；只跑 `vite dev` 仅本地 5173 生效，不影响容器内页面。

### 3. 代码热更新（开发模式）
`server/`、`server/ai_service/`、`server/orchestrator/` 以 bind mount 挂进容器。**开发中改 Python 代码后无需重建镜像**，重启对应容器即可生效：
```bash
docker compose restart reelmind-server reelmind-ai reelmind-orchestrator
```
> 改了 `requirements.txt` / `package.json` 则必须重建镜像：`docker compose build <服务名>`。

### 4. GPU 与 AI
- AI 容器 `runtime: nvidia`，需要宿主机已装 NVIDIA 驱动 + nvidia-container-toolkit；无 GPU 会启动失败。
- 模型首次运行自动下载到 `/data/reelmind/models`（挂载卷），体积大（whisper large-v3 约 3GB+），**首次启动慢属正常**。
- 用不了大模型的低内存设备：`WHISPER_MODEL=tiny`、`ENABLE_CLIP=false`。

### 5. 数据与备份
- 数据三处：PG（`PGDATA_ROOT`）、SQLite + 媒体（`REELMIND_DATA_ROOT`）、Redis（`REDIS_DATA_ROOT`）。
- **数据库备份用 `scripts/backup.sh`**：`./scripts/backup.sh <描述> --db`（PG pg_dump + SQLite 复制）。
- 删除资产前先备份；涉及迁移/清理前必备份（铁律 R6.2）。

### 6. 常见故障排查

| 现象 | 排查 |
|------|------|
| 前端白屏 / 页面 404 | `web/dist` 是否构建过？`npm run build` 后再起容器 |
| `/api/ping` 通但页面 500 | `docker logs reelmind-server` 看 traceback |
| AI 卡住不动 | `docker logs reelmind-ai`；查 `ai_engine_jobs` 表状态 |
| 模型一直下载 | 检查 `data/reelmind/models` 卷是否可达、磁盘空间 |
| 端口占用 | 改 `.env` 的 `PORT_MAP` 后 `docker compose up -d` |
| 数据库连不上 | `docker compose logs postgres`；检查 `.env` DB_* 项 |

### 7. 健康自检命令（部署后跑一遍）

```bash
# 铁律硬规则自查（仓库脚本，13 项）
./scripts/check.sh

# 三连探活
docker compose ps
curl http://localhost:2588/api/ping
curl http://localhost:2589/health
```
