### WP1：`check.sh` 可靠化

**做什么**

1. 脚本开头（`set -u` 后、`cd` 前）加 PATH 兜底与工具自检（`dirname` 必须先于 cd 自检）：

```bash
# Windows 非登录 shell 下 Git Bash 的 PATH 可能缺 /usr/bin，先兜底再自检
export PATH="/usr/bin:/bin:/mingw64/bin:$PATH"

REQUIRED_TOOLS="dirname grep awk find xargs tr sed sort head wc git"
MISSING=""
for t in $REQUIRED_TOOLS; do
  command -v "$t" >/dev/null 2>&1 || MISSING="$MISSING $t"
done
if [ -n "$MISSING" ]; then
  echo "❌ check.sh 运行环境缺工具:$MISSING（Windows 请使用 Git Bash 完整环境）" >&2
  exit 2
fi
```

2. R1.1 检查范围 `server/app/api/` → `server/app/`（覆盖 `server/app/ml/`，不扫 `server/ai_service/`）。
3. 新增 R3.1 检查：`web/src/api/client.ts` 行数 >50 即违规（full + staged 两模式）。
4. R1.3 检查升级为"白名单外禁止写"（覆盖裸 SQL + 单行 ORM 批量写）：

```bash
grep -rnE "INSERT INTO ai_engine_jobs|UPDATE[[:space:]]+ai_engine_jobs|DELETE FROM ai_engine_jobs|UPDATE[[:space:]]+processing_state" server --include="*.py" \
  | grep -vE "alembic|migration" \
  | grep -vE "^server/app/core/job_helpers\.py:|^server/ai_service/job_helpers\.py:"

# ORM 批量写（单行命中）：query(AIEngineJob)...update(
grep -rnE "query\(AIEngineJob\).*\.update\(" server --include="*.py" \
  | grep -vE "alembic|migration|job_helpers\.py"
```

staged 模式对暂存 py 文件套同一逻辑。

> 多行 ORM 写（`q.update(` 与 `AIEngineJob` 分行的形式，如 `pipeline.py:196-211`）单行 grep 覆盖不到，实施后以 `rg -nU "query\(AIEngineJob\)[\s\S]{0,400}?\.update\(" server` 人工核对兜底，并靠 WP2 收口保证白名单外零命中。

5. 修正 R2.5 全量模式误输出：无 Card/Item/Row 组件时不应显示 "(staged) 暂存区无列表项组件"，改为模式无关文案。

**不做什么**：不把脚本改成 PowerShell 实现；不改 Windows PATH 本身；不新增 CI。

**验收**：非登录环境缺工具时 `exit 2` 且输出明确；登录环境全量通过（WP2/WP3 完成后）；`INSERT INTO ai_engine_jobs` 能被 R1.3 抓到。
