# 07 数据规范

> 对应铁律：R6.1-R6.3
> 作用：数据库变更、数据备份、数据删除的边界。数据是本项目最不可再生的资产（视频元数据 + AI 推理结果），优先级高于一切代码。

---

## R6.1 模型变更走迁移

**边界**：改 SQLAlchemy 模型（`server/app/models/`）或需要改表结构时，必须走 alembic 迁移，禁止手动 `ALTER TABLE` / `CREATE TABLE`。

```bash
# ✅ 标准流程
# 1. 改 models/ 下的 ORM 文件
# 2. 生成迁移
docker compose exec reelmind-server alembic revision --autogenerate -m "描述"
# 3. 审查生成的迁移文件（autogenerate 可能误判，必须人工看 diff）
# 4. 执行
docker compose exec reelmind-server alembic upgrade head
# 5. 验证表结构
docker compose exec postgres psql -U reelmind -c "\d 表名"
```

**禁止**：
- 直接 `psql -c "ALTER TABLE ..."` 改生产表（除非紧急事故且先备份）
- 只改模型不生成迁移（模型与库不一致 → 运行时崩溃）
- autogenerate 生成后不审查直接执行

**检查**：
```bash
# 非迁移目录中出现 DDL 即违规
grep -rn "ALTER TABLE\|CREATE TABLE\|DROP TABLE" server/app/ server/ai_service/ --include="*.py" | grep -v alembic
```

## R6.2 数据先备份后动

**边界**：任何涉及数据库写操作（迁移 / 清理 / 导入 / 大量 UPDATE）前，必须先备份对应库。与 R0.3（代码备份）同级，不可跳过。

```bash
# PG 备份
docker compose exec postgres pg_dump -U reelmind -F c -f /tmp/reelmind_$(date +%Y%m%d).dump reelmind

# SQLite 备份（复制 .db 文件）
cp data/reelmind.db backups/20260902_数据变更/reelmind.db
```

**禁止**：
- 不备份就执行迁移 / 清理 / 导入
- 用"只是测试环境"当借口跳过备份

**检查**：人工流程，脚本 `backup.sh` 支持数据库备份辅助（见其文档）。

## R6.3 删除走闭环

**边界**：删除资产时必须同时清理所有关联数据，禁止残留孤儿数据。

| 删除对象 | 必须同步清理 |
|---------|-------------|
| 资产 (asset) | 场景、字幕、标签、OCR、CLIP 向量、ai_engine_jobs 记录、预览文件 |
| 库 (library) | 库下所有资产 + 资产关联数据 |
| 标签 (tag) | 所有 asset_tags 关联 |

**禁止**：只删主记录，留下场景/字幕/向量等孤儿数据（会导致前端展示错误、搜索脏数据、存储泄漏）。

**检查**：删除接口代码评审时必查关联清理逻辑。
