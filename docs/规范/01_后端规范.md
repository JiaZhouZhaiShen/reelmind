# 01 后端规范

> 对应铁律：R1.1-R1.5
> 作用：FastAPI 后端（server/）与 AI 服务（ai_service/）的架构边界与检查方法。

---

## R1.1 Server 只转发不做计算

**边界**：
- Server 不加载 AI 模型（torch/transformers/模型权重）
- Server 不做 GPU 推理，AI 请求经 HTTP proxy 转发到 AI 容器（2589）

```python
# ✅ 转发
result = await _ai_post("/pipeline/start", {...})
# ❌ 在 server 里调模型推理
```

**检查**：
```bash
grep -rn "torch\|transformers\|model\.predict\|model\.encode" server/app/
```

**例外**：Server 可做非 AI 的业务计算（聚合、状态推导、文件扫描）。

## R1.2 双数据库各司其职

| 数据 | 存哪里 | 谁写 | 谁读 |
|------|--------|------|------|
| Asset 元数据、管道状态 | PG | Server + Orchestrator + AI Worker | Server |
| AI 推理结果（场景/字幕/标签/OCR） | SQLite | AI Worker | Server |
| CLIP 向量索引 | PG (pgvector) | AI Worker | Server |

**边界**：不存在一条数据同时写两个库。发现双写 = 设计有问题。

## R1.3 状态唯一写入口

**边界**：每个容器只有一个状态写入口模块——Server = `app/core/job_helpers.py`，AI = `ai_service/job_helpers.py`。其余代码禁止直接写 `ai_engine_jobs` / `processing_state`；批量 claim / recover / reclaim / 标记完成等原子写统一封装在 `job_helpers` 内。

```python
# ✅
from app.core.job_helpers import set_job_status
set_job_status(session, media_id, "scene", "completed")
# ✅ AI 容器（ai_service/job_helpers.py 为唯一写入口）
from job_helpers import set_job_status
set_job_status(media_id, "scene", "completed")
# ❌
cur.execute("UPDATE ai_engine_jobs SET status = 'completed' WHERE id = ?")
```

**检查**：
```bash
grep -rnE "INSERT INTO ai_engine_jobs|UPDATE[[:space:]]+ai_engine_jobs|DELETE FROM ai_engine_jobs|UPDATE[[:space:]]+processing_state" server --include="*.py" | grep -vE "alembic|migration|job_helpers\.py"
```

## R1.4 接口职责单一

**边界**：`api/*.py` ≤1000 行；`core/` 等非 api 文件超行也应收敛。同一文件处理多个无关职责比行数超限更应优先拆。

> 说明：原阈值 500 行对大型接口过紧，经 2026-09-02 评审调整为 1000 行（与前端 R2.10 一致）。仍属硬上限，超限即拆。

**检查**：
```bash
find server/app/api -name "*.py" -exec wc -l {} \; | awk '$1 > 1000'
```

**现状（2026-09-02 实测）**：`core/indexer.py` 1323、`ai_service/pipeline.py` 1010（超 1000 行，待收敛）；`api/ai/pipeline.py` 701、`api/search.py` 650（1000 行阈值下合规）。

## R1.5 后端不做渲染计算

- 放前端的信号：把数字转百分比、算进度条、格式化时间
- 放后端的信号：解析逻辑需要知道后端内部协议细节（如 step 字符串格式）

```python
# ✅ 后端只返回原始数据
{"engines": {"scene": "completed", "yolo": "running"}, "step": "YOLO [5/10]"}
# ❌ 后端写 40 行进度推算
```

**例外**：业务聚合与状态推导（如 results_ready 判断）可留后端。
