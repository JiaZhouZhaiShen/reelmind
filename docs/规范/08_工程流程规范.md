# 08 工程流程规范

> 对应铁律：R7.1-R7.3
> 作用：依赖变更、配置变更、新增模块的工程操作边界。

---

## R7.1 依赖变更必重建

**边界**：改 `server/requirements.txt` / `server/ai_service/requirements.txt` / `web/package.json` 后，必须重建对应镜像验证，不能只改文件。

```bash
# 改了 server/requirements.txt
docker compose build reelmind-server

# 改了 ai_service/requirements.txt
docker compose build reelmind-ai

# 改了 web/package.json
cd web && npm install && npm run build
```

**禁止**：
- 改依赖后不重建镜像（容器内还是旧依赖，行为不一致）
- 新增依赖不验证是否已存在于其他容器（重复依赖 → 镜像膨胀）

## R7.2 配置变更必验证

**边界**：改 `.env` / `server/app/config.py` 后必须重启容器验证生效。

```bash
# 改了 .env
docker compose restart reelmind-server reelmind-ai reelmind-orchestrator
# 验证
docker logs reelmind-server | grep "配置\|config"
```

**禁止**：
- `.env` 提交入库（含真密码/令牌）。已由 `.gitignore` 排除，`git add -f .env` 即违规。
- 改配置不重启就说"生效了"

**检查**：
```bash
# .env 是否被 git 追踪（应为空）
git ls-files | grep -E "^\.env$"
```

## R7.3 新增模块必注册

**边界**：新增容器 / 服务 / 引擎 / 目录时，必须同步更新：

| 新增对象 | 必须同步 |
|---------|---------|
| 新容器 | `docker-compose.yml` 服务定义 + `docs/必读_README.md` 容器表 + CLAUDE.md 架构表 |
| 新 AI 引擎 | `docs/规范/01_后端规范.md` / AI 管线文档 |
| 新路由文件 | `web/src/api/` 对应 api 文件（遵循 R3.1） |
| 新 store | 遵循 R2.1，按域拆文件 |

**禁止**：加了新容器/服务但文档和 compose 不同步（导致别人找不到、环境起不来）。

**检查**：新增模块的 PR/方案必须包含文档同步项。
