# 05 容器规范

> 对应铁律：R5.1-R5.3
> 作用：Docker 部署（docker-compose.yml）的架构边界与安全检查。

---

## R5.1 AI/Orchestrator 必须 stateless

**边界**：容器删了重建不影响任何数据。AI 模型权重预装在镜像里。

| 容器 | 卷需求 |
|------|--------|
| postgres | PG data |
| reelmind-server | SQLite + 媒体库 |
| reelmind-orchestrator | 无（stateless） |
| reelmind-ai | 仅共享卷（媒体只读 + SQLite 读写） |

**检查**：确认容器写的路径都在挂载卷内，而非容器本地。

## R5.2 禁止 docker.sock 挂载

**边界**：任何容器不得挂载 `/var/run/docker.sock`。这是容器逃逸入口。

```yaml
# ❌ 禁止
volumes:
  - /var/run/docker.sock:/var/run/docker.sock:rw
```

**检查**：
```bash
grep "docker.sock" docker-compose*.yml
```

**现状（2026-09-02 实测）**：docker-compose.yml 仅有注释提及"已移除"，无实际挂载，合规。

## R5.3 跨容器可追踪

**边界**：所有跨容器请求透传 `trace_id`，日志使用结构化格式，写到 stdout 不走文件。

```python
logger.info("pipeline_step", trace_id="abc123", engine="scene", step=5, total=10)
```

**检查**：
```bash
grep -rn "trace_id\|structlog" server/app/ server/ai_service/
```

**注意**：此条为演进方向，**当前未实现**（2026-09-02 实测全仓 `trace_id` 出现 0 处）。属待立项改进项，不作为阻塞项。
