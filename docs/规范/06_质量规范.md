# 06 质量规范

> 对应铁律：R0.6（质量通用标准，适用于 R0-R7 所有层）
> 作用：命名、提交、格式、文档维护的统一标准。

---

## 一、新增文件规范

| 文件类型 | 放哪里 | 命名规范 |
|----------|--------|---------|
| Python API 路由 | `server/app/api/` | 蛇形，如 `tag_export.py` |
| Python 模型 | `server/app/models/` | 蛇形 |
| React 页面 | `web/src/pages/` | PascalCase，如 `VideoDetail.tsx` |
| React 组件 | `web/src/components/` | PascalCase，功能子目录分组 |
| Zustand store | `web/src/stores/` | 小驼峰，如 `videoStore.ts` |
| API 模块 | `web/src/api/` | 小驼峰，如 `videoApi.ts` |
| 文档 | `docs/` | 中文命名，`必读_` 前缀表示新人必读 |

## 二、Git 提交规范

```
格式：<type>(<scope>): <subject>
type: feat / fix / refactor / style / docs / chore / perf / test
scope: server / web / ai / orchestrator / docker / docs

✅ feat(web): 添加视频批量删除功能
✅ fix(server): 修复扫描时 N+1 查询
❌ update / fix bug / 改了点东西
```

**禁止**：
- 直接 push 到 main 分支
- 提交 .bak / .refactor-backup / .original 文件
- 在同一个提交中混入无关改动（修 bug 时顺带改格式 → 拆两个提交）
- 空 commit message

## 三、代码格式

```bash
# 后端 — 提交前必须跑
cd server && black --line-length=100 .

# 前端 — 提交前必须跑
cd web && npx prettier --write "src/**/*.{ts,tsx,css}"

# 类型检查（CI 防线）
cd web && npm run typecheck
```

## 四、铁律自查（提交前必跑）

```bash
# 硬规则全量检查
./scripts/check.sh

# 铁律对照（完整版）
cat docs/铁律.md
```

## 五、文档维护

- `docs/铁律.md` 是唯一铁律真相源，其他文档不得复述铁律细节（防漂移）
- 改铁律 → 同步改规范 + 脚本 + 修订记录（四步闭环）
- 方案文档命名：`方案_<主题>.md`，评审通过后按需归档
- 当前源码行数超标文件（2026-09-02）：见 `docs/规范/01_后端规范.md`，属渐进收敛项
