# 00 工作流程规范

> 对应铁律：R0.1-R0.6
> 作用：指导 AGENT 每次改动的完整流程，明确"什么能做什么不能做"。

---

## 一、全流程总纲

```
思考 → 方案 → 验证 → 确认 → 备份 → 修改 → 验证 → 删备份
```

每个环节的含义与产出：

| 环节 | 做什么 | 产出 |
|------|--------|------|
| 思考 | 理解需求，判断影响面，识别风险 | 改动计划（心里有数） |
| 方案 | 给出具体改动方案（文件/行/改法） | 方案文档或方案段落 |
| 验证 | 验证方案与现状是否一致、是否可行 | 验证结论 |
| 确认 | 等用户确认方案（重大改动必须） | 用户同意 |
| 备份 | 备份到 `backups/{时间戳}_{描述}/` | 备份文件 |
| 修改 | 按方案精确修改 | 改动后的代码 |
| 验证 | 功能/回归/格式验证 | 验证结果 |
| 删备份 | 验证通过后清理备份 | 干净目录 |

## 二、R0.1 先验证再动手

改动前必须确认当前状态，禁止凭印象改：

```bash
# 1. 确认要改的文件当前内容（用 Read 工具）
# 2. 确认环境状态
docker compose ps
curl http://localhost:2588/api/ping
curl http://localhost:2589/health
# 3. 确认改动基线
#    修 bug   → 先复现 bug，确认问题存在
#    改行为  → 先确认当前行为
#    重构    → 先确认现有逻辑与测试
```

**违反示例**：直接写代码修 bug，没先确认 bug 是否真实存在 → 改了没用的地方。

## 三、R0.2 先方案后代码

- 单文件小改动、明确无歧义 → 可直接改
- 跨文件、涉及数据库、涉及行为变更、重构 → 必须先出方案，验证后确认再改
- 拿不准是否要确认 → 宁可多问一句

## 四、R0.3 备份铁律

```bash
# 统一用 backup.sh，或手动：
mkdir -p backups/20260902_113001_铁律重构   # 格式：{YYYYMMDD_HHMMSS}_{描述}（与 backup.sh 一致）
cp <要改的文件> backups/20260902_113001_铁律重构/
```

- 修改任何文件前必须先备份，备份完成前不允许修改
- 修改并验证通过后，备份才可删除
- 备份目录统一放项目根 `backups/`

## 五、R0.4 最小改动

**可以做**：任务明确要求的文件、行、逻辑改动；提出方案与现状的矛盾、风险、副作用（这是正确行为）。

**禁止**：
- 顺手重构/格式化/优化与任务无关的代码
- "顺便修"不相关的 bug
- 自行扩展方案意图扩大改动范围
- 遇到错误时自行尝试多种修复——应停止并报告

## 六、R0.5 方案必有边界

每个方案（无论大小）必须明确写出边界，边界内严格执行，边界外不做。

**方案必含四要素**：

```
① 做什么     —— 本次改动的目标与内容
② 不做什么   —— 明确排除的项（防止顺手改/扩大范围）
③ 涉及文件   —— 将修改/新增/删除的文件清单
④ 验收标准   —— 怎么判断改对了（功能/代码/回归）
```

**执行规则**：
- 方案确认后，只做 ①③ 范围内的事
- 发现 ② 中的问题（或任何边界外的问题）→ **提出，不擅自改**
- 需要扩大边界 → 必须重新出方案并确认，不能"边做边扩"
- 边界外改动即使"顺手就能修"也禁止——记录为独立待办

**典型违反**：
- 修 bug 时"顺便"把相关代码重构了 → 违反边界
- 改前端时发现后端 bug 顺手修了 → 违反边界
- 方案只说"优化搜索"，实际连 API 一起改了 → 违反边界

## 七、禁止行为汇总

```
❌ 不验证就改代码
❌ 重大改动不确认就动手
❌ 不备份就改文件
❌ 顺手改不相关的东西
❌ 遇到问题不报告，自己瞎修
❌ 方案边界外擅自动手
```

## 八、验收四标准（改动完成后必走）

每做一次改动，按 **修改 → 执行 → 验收** 三步走，验收必须过四项：

### ① 功能验收

```
[ ] 改了的东西，功能符合预期吗？
    → 修 bug：bug 不再复现
    → 加功能：新功能按设计工作
    → 重构：行为没变但代码更好了
[ ] API 通了吗？  curl http://localhost:2588/api/ping
[ ] AI 通了吗？   curl http://localhost:2589/health
```

### ② 代码验收

```
[ ] cd web && npm run typecheck    # 前端无类型错误
[ ] ./scripts/check.sh                # 铁律硬规则自查（0 新增违规）
[ ] 没有新增空 catch / .bak / 硬编码中文
[ ] 涉及 ai_engine_jobs → 用了 set_job_status
[ ] 涉及数据库 → 走了 alembic 迁移（R6.1）
[ ] 涉及依赖 → 重建了镜像（R7.1）
[ ] 涉及配置 → 重启验证了生效（R7.2）
[ ] 新增文件放对了位置、命对了名
```

### ③ 回归验收

```
[ ] 改了后端 → 现有主要前端页面正常显示
[ ] 改了前端 → 页面渲染正常，API 无 500
[ ] 改了模型 → migration 正常升级
[ ] 改了配置 → 容器重启后配置持久化
[ ] 改了什么 → 对应的 docs/ 文档更新了吗（R7.3）
```

### ④ 最终确认

```
[ ] 从头看一遍自己改的 diff（git diff）
[ ] 和先验证时的基线对比，确认改的就是要改的
[ ] 没有遗留的调试代码（console.log / print / TODO）
```
