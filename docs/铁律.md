# REELMIND 铁律

> 本文档是 REELMIND 的铁律本体，只写原则与边界，**指导作用优先**。
> 每条铁律 = 编号 + 一句话原则。执行细则见 `docs/规范/`，机器检查见 `scripts/check.sh`。
> 具体问题（bug/优化/重构）不在此找答案——按 `docs/规范/00_工作流程.md` 的流程产出方案解决。
> 修订本文档必须同步更新对应规范 + 脚本 + `docs/铁律修订记录.md`（四步闭环）。

## 〇、工作流程铁律（总纲）

> 思考 → 方案 → 验证 → 确认 → 备份 → 修改 → 验证 → 删备份

| 编号 | 铁律 | 规范 | 脚本 |
|------|------|------|------|
| R0.1 | 先验证再动手：改前先 Read 确认基线；修 bug 先复现、改行为先确认、重构先确认逻辑。不验证就改 = 改坏了不负责 | 00 | — |
| R0.2 | 先方案后代码：改动前先出方案，验证后确认，确认后备份再改。重大改动不确认不动手 | 00 | — |
| R0.3 | 备份铁律：修改任何文件前备份到 `backups/{时间戳}_{描述}/`，验证通过才删备份 | 00 | backup.sh |
| R0.4 | 最小改动：只做任务范围内的事；不顺手修 bug、不顺手重构、不扩大范围。发现问题可提出，不擅自改 | 00 | — |
| R0.5 | 方案必有边界：每个方案必须明确范围与边界（做什么/不做什么/涉及文件/验收标准）；边界内严格执行，边界外不做，变更边界须重新确认 | 00 | — |
| R0.6 | 质量通用标准：命名/提交/格式/文档维护统一执行 `docs/规范/06_质量规范.md`，所有层均适用 | 06 | — |

## 一、后端铁律

| 编号 | 铁律 | 规范 | 脚本 |
|------|------|------|------|
| R1.1 | Server 只转发不做计算：不加载 AI 模型、不做 GPU 推理，AI 请求一律 HTTP 转发 AI 容器 | 01 | check.sh |
| R1.2 | 双数据库各司其职：状态/元数据 → PG；AI 推理结果 → SQLite；向量 → PG(pgvector)。不存在一条数据双写 | 01 | — |
| R1.3 | 状态唯一写入口：每个容器只有一个写入口模块（Server = `app/core/job_helpers.py`，AI = `ai_service/job_helpers.py`），其余代码禁止直接写 `ai_engine_jobs` / `processing_state` | 01 | check.sh |
| R1.4 | 接口职责单一：api 文件 ≤1000 行，职责单一优先于行数；超限即拆 | 01 | check.sh |
| R1.5 | 后端不做渲染计算：进度百分比、格式化交给前端；业务聚合/状态推导可留后端 | 01 | — |

## 二、前端铁律

| 编号 | 铁律 | 规范 | 脚本 |
|------|------|------|------|
| R2.1 | 业务状态归 store：API 数据必须进 Zustand store；组件 `useState` 只存 UI 状态 | 02 | — |
| R2.2 | 子组件从 store 读数据：不通过父组件穿透业务 props（>5 个即警告） | 02 | — |
| R2.3 | 组件自包含三态：每个组件自己处理 loading/error/empty，不依赖父组件 | 02 | — |
| R2.4 | 整页 ErrorBoundary：每个路由页面外层必须包 ErrorBoundary | 02 | — |
| R2.5 | 高频组件加 memo：列表项/卡片/侧边栏等高频组件用 `React.memo`；全项目零 memo 是性能 bug | 02 | check.sh |
| R2.6 | 禁止空 catch：每个 catch 必须有用户可见反馈（例外：video.play/clipboard/SSE 解析） | 02 | check.sh |
| R2.7 | i18n 禁硬编码中文：用户可见文本一律 `t('key')` | 02 | check.sh |
| R2.8 | 无死代码残留：源码目录禁止 `.bak`/`.refactor-backup`/`.original`/零引用页面 | 02 | check.sh |
| R2.9 | TS 严格模式：`strict` + `noUnusedLocals` + `noUnusedParameters` 必须开启 | 02 | check.sh |
| R2.10 | 页面组件 ≤1000 行：超过即拆分子组件（pages/ 与 components/ 均适用） | 02 | check.sh |
