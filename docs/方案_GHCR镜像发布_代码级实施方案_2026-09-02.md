### 2.2 新建 `.github/workflows/publish-images.yml`

骨架（关键内容，实施时按仓库实际微调）：

```yaml
name: Publish GHCR images

on:
  push:
    tags: ['v*']
  workflow_dispatch:

permissions:
  contents: read
  packages: write

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up QEMU
        uses: docker/setup-qemu-action@v3

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Compute image tags
        id: meta
        run: |
          if [ "$GITHUB_REF_TYPE" = "tag" ]; then
            # 保留 git tag 全名（含 v 前缀），与文档示例一致
            echo "tag1=${GITHUB_REF_NAME}" >> "$GITHUB_OUTPUT"
            echo "tag2=latest" >> "$GITHUB_OUTPUT"
          else
            echo "tag1=latest" >> "$GITHUB_OUTPUT"
            echo "tag2=main-${GITHUB_SHA::7}" >> "$GITHUB_OUTPUT"
          fi

      - name: Build and push server
        uses: docker/build-push-action@v6
        with:
          context: .
          file: server/Dockerfile.slim
          push: true
          tags: |
            ghcr.io/jiazhouzhaishen/reelmind-server:${{ steps.meta.outputs.tag1 }}
            ghcr.io/jiazhouzhaishen/reelmind-server:${{ steps.meta.outputs.tag2 }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

      # orchestrator / ai / nginx 三个 job 或 step 同构，文件与 tag 名对应：
      # orchestrator -> file: server/orchestrator/Dockerfile, image: ghcr.io/jiazhouzhaishen/reelmind-orchestrator
      # ai           -> file: server/ai_service/Dockerfile,  image: ghcr.io/jiazhouzhaishen/reelmind-ai
      # nginx        -> context: ./nginx,                   image: ghcr.io/jiazhouzhaishen/reelmind-nginx
      # 每个 step 的 tags 都写两行完整镜像引用（复用 steps.meta.outputs.tag1/tag2），禁止拼成"前缀:tag1,tag2"
```

> 说明：
> - 镜像 tag 与 git tag 同名（含 `v` 前缀），例如 git tag `v9.26.0901` 推 `v9.26.0901` 与 `latest` 两个镜像 tag；`workflow_dispatch`（非 tag 事件，`GITHUB_REF_TYPE != tag`）推 `latest` 与 `main-{sha}`。
> - build-push-action 的 `tags:` 每一行必须是**完整镜像引用**（`ghcr.io/owner/image:tag`）。不要输出"版本号,latest"再拼到前缀后面，否则裸 `latest` 会被解析成 `docker.io/library/latest` 导致推送失败。
> - 4 个镜像用 4 个 step（或 matrix：`file`/`image` 数组）均可；用 matrix 时 meta 的 tag1/tag2 逻辑不变。
> - 不重推 `v0.1.0`，即不会为旧版本重复构建；后续统一用 `v9.26.0901` 及以上版本。

注意：
- GHCR 包名用小写：`ghcr.io/jiazhouzhaishen/...`。
- 4 个镜像分开 step，便于失败定位与并行（也可用 matrix）。
- AI 镜像构建可能超过 30 分钟；GitHub 免费 runner 单 job 上限 6 小时，一般可行，但建议先在本地 `docker compose build reelmind-ai` 验证 Dockerfile 能完整构建。

## 三、首次发布操作（实施者执行）

```bash
# 1. 本地验证 4 个 Dockerfile 都能构建（可选，AI 镜像慢）
docker compose build reelmind-server reelmind-orchestrator reelmind-nginx
# AI 镜像单独构建验证（耗时）
docker compose build reelmind-ai

# 2. 提交上述改动并推送（tag 触发发布，或先 workflow_dispatch）
git push github main

# 3. 手动触发一次（首次上线推荐，避免先打 tag）
gh workflow run publish-images.yml --repo JiaZhouZhaiShen/reelmind
gh run watch --repo JiaZhouZhaiShen/reelmind
```

   - Package settings → Danger Zone → Change visibility → Public。
